## Fixed defects

| Defect | Previous behavior | Fix and verification |
|---|---|---|
| Media-only post context | A post with media and no text could be rejected as missing | Accept verified post IDs with text **or** media; get_tweet and prepare_reply regressions |
| Delayed target hydration | A visible parent card could appear before the requested post and trigger a premature not-found result | Bounded target wait and fresh lookup; fictional delayed DOM tests and successful live retest |
| Followers/following with bio mentions | Other profile links in a bio made the account identity ambiguous | Require matching avatar owner and exact visible handle link; genuine ambiguity still fails closed; both live list types retested |
| Missing engagement counts | Absent metrics were converted into zero | Preserve null for unavailable evidence; explicit zero controls still parse as zero |
| Inline cookie diagnostics | Inline cookie presence was reported as valid without equivalent content validation | Reuse strict cookie validation; malformed/expired examples return problems |
| Rejected campaign reservations | A rejected draft could indefinitely block that lead in a different campaign | Derive reservation state from explicit draft outcomes; missing, failed and uncertain outcomes remain blocked |
| Concurrent stdio processes | Two servers could load separate cached draft/queue state for one data home | Acquire OS ownership before loading stores; same-home refusal, different-home use and crash-release tests |
| Package/executable mismatch | uvx x-use-mcp==3.0.0 failed because only x-use existed | Add x-use-mcp entry point that starts MCP directly; test real initialization from an installed wheel |
| Discovery documentation | Broken PyPI-relative links and overbroad capability claims | Absolute README links, precise metadata and separate released/development capability statements |

The ownership lock coordinates one host and one canonical X_USE_HOME. Do not point different data homes at the same custom journal files. Embedded create_server users must provide equivalent lifecycle ownership. This is not distributed multi-host storage coordination.

## New tools

### get_runtime_info

Read-only local diagnostics: server/Python/package versions, SDK protocol version, backend, draft mode, auto-drain state and registered tool count. It does not start a browser or reveal account identities, local paths, credentials or environment values. Its live_authentication_checked field is false: configuration is not proof of a valid X session.

### preview_campaign_message

Render one existing campaign member's exact message and eligibility reasons without creating a draft or reserving a send. Checks account activity, campaign state, membership, lead status, suppression and existing reservations. Tests cover purity, account isolation, rejected/executed/uncertain states and missing drafts. A preview does not grant permission to send and must be rechecked when a draft is created.

## Complete MCP protocol coverage

[scripts/audit_mcp.py](../scripts/audit_mcp.py) launches the actual stdio subprocess with the MCP Python client in a temporary, credential-free data home. It validates tool schemas, annotations, text/structured-result agreement and isError behavior. Expected missing-account or invalid-input errors count as contract checks, not successful external operations.

The run makes 72 empty-home contract calls, 54 local workflow calls and four restart checks. Local workflows include account/proxy configuration, draft inspection/rejection, rejected approval refusal, queue cancellation, leads, campaigns, suppression, preview purity and cancelled thread continuation. No external writes occur in this harness.

The full sanitized installed-wheel transcript is [protocol.json](audit-2026-10-12/protocol.json). The [per-tool coverage CSV](audit-2026-10-12/tool-coverage.csv) separates protocol contracts, local workflow checks and live observations. The broader [tool validation matrix](TOOL_VALIDATION.md) retains earlier release-specific evidence and fixture references.

Reproduce the credential-free audit after installation:

```bash
python scripts/audit_mcp.py --report audit-protocol.json
python scripts/ci_browser_smoke.py --mode all --expect-installed
```

Use a clean wheel environment for --expect-installed; it intentionally rejects an editable/source import. Browser smoke needs the selected matching Chromium. [CONTRIBUTING](../CONTRIBUTING.md) documents required native fixtures and CI partitions.

## Authorized live checks

The supplied session was imported into a private data directory outside the repository. Authentication material and the owner's inbox PIN were not added to source, documentation or committed artifacts.

- Profile, profile context, recent posts, profile search, keyword search, home feed, thread context and notifications returned visible evidence.
- Followers and following initially encountered the bio-link defect. Both returned bounded results after the fix.
- Single-post reads and reply context initially failed on target timing; both succeeded after the hydration fix.
- Analytics returned available=false and premium_required, without invented metrics.
- Inbox access correctly stopped at pin_required. After the owner supplied recovery authorization, unlock, conversation reading, inbox/request/other folders, unread/read filters and conversation search completed.
- Exactly one authorized test message was drafted and approved for the user-specified recipient. The send returned confirmation with message identity, and a separate conversation read found the exact test text once. Recipient identity and private conversation data are intentionally omitted here.

Opening conversations/notifications can mark them read. The empty read-filter result is a partial visible-window observation, not proof that an account has no read conversations. No public posts, follows, likes or other unsolicited messages were used as live tests.

Live reads respected the runtime's pacing/cooldown feedback. These observed delays are policy and network/UI effects, not a throughput benchmark.

## What remains unverified or limited

- No live mass campaign, public publishing, follow/like/repost cycle or legacy unattended batch was executed. Their behavior is covered by isolated contracts and fictional browser/workflow fixtures.
- Optional paid LLM generation and real third-party proxies were not configured for this account. Their unit/mock coverage is not a live provider test.
- Premium analytics dashboard layouts remain unsupported without eligible observed evidence.
- Inbox/thread/connection reads remain bounded and partial; changing X layouts can require new fixtures and selector fixes.
- SDK v1 compatibility is intentional. Current official Python SDK releases include stable v2; this checkout remains on mcp>=1.30,<2 with negotiated protocol 2025-11-25. A v2 migration needs its own compatibility work. [SDK releases](https://github.com/modelcontextprotocol/python-sdk/releases), [migration guide](https://py.sdk.modelcontextprotocol.io/migration/).
- The complete cross-platform CI and container matrix must run after publication is authorized. No GitHub push or release occurred during this work.
